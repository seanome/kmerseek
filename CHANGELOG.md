# Changelog

## 0.4.0

- Added Rust-based k-mer search, replacing sourmash's search so that results can report which sub-sequences overlap and what they look like in the reduced alphabet ([#25](https://github.com/seanome/kmerseek/pull/25))
- Added the named HP alphabet variants (Lehninger, Thomas-Dill, Kyte-Doolittle, and the cysteine-handling variants), which differ in how they classify the borderline residues C, G, P, W and Y ([#26](https://github.com/seanome/kmerseek/pull/26))
- Added a simple visualization of target hits against a query sequence, showing both the original and encoded alphabets ([#28](https://github.com/seanome/kmerseek/pull/28))
- Added removal of hits with uncorrected p-value > 0.05, since those are removed anyway after BH correction ([#27](https://github.com/seanome/kmerseek/pull/27))
- Added filtering by at least 2 shared hashes per hit to remove spurious hits ([#27](https://github.com/seanome/kmerseek/pull/27))
- Added a table of HP encodings to the README ([#33](https://github.com/seanome/kmerseek/pull/33))
- Removed the `--scaled` option since we always use `--scaled 1` anyway ([#30](https://github.com/seanome/kmerseek/pull/30))
- Streamed `visualize_hits.py` CSV loading through a polars `LazyFrame` instead of holding every row in memory and rescanning it per query; plotting every query in a 94 MB results file went from 38 s to 1.3 s ([#31](https://github.com/seanome/kmerseek/pull/31))
- Sorted top hits in the visualization by Benjamini-Hochberg corrected p-value (q-value) instead of containment ([#32](https://github.com/seanome/kmerseek/pull/32))
- Replaced invented placeholder motifs with real CED9/BCL2 residues and their actual Thomas-Dill HP encoding in `visualize_hits` tests ([#35](https://github.com/seanome/kmerseek/pull/35))
- Logged the k-mer frequency histogram and top/bottom 10 k-mers during indexing, with `--kmer-stats-out` to save the spectrum as CSV ([#36](https://github.com/seanome/kmerseek/pull/36))
- Added `--remove-low-complexity` to drop homopolymer k-mers (e.g. poly-glutamate tracts, all-hydrophobic HP windows) at index time; the setting is stored in the index and applied automatically at search time ([#37](https://github.com/seanome/kmerseek/pull/37))
- Added region-scoped scoring (`region_poisson_score`, `region_tail_probability`, `region_enrichment`, and related columns) so a matched sub-region is scored on its own instead of being diluted by the whole protein; added `--min-region-score`, deprecated `--max-pvalue` in favor of `--max-query-pvalue`, and renamed several result columns (`poisson_pvalue` → `query_poisson_pvalue`, `query_start`/`query_end`/`query_subseq` → `region_start`/`region_end`/`region_subseq`) ([#38](https://github.com/seanome/kmerseek/pull/38))
- Fixed ambiguous amino acids (B/J/Z) to resolve deterministically instead of by random draw, making indexing reproducible; U and O now map to C and K instead of being treated as unknown ([#39](https://github.com/seanome/kmerseek/pull/39))
- Built the k-mer frequency spectrum once instead of scanning it 9 times during indexing (up to 4.4x faster), and fixed gzip output silently truncating on write errors ([#40](https://github.com/seanome/kmerseek/pull/40))
- Fixed a panic when indexing with `--ksize 0`; k-mer sizes of 0 or above 100 are now rejected with a clear error instead of crashing or silently doing nothing ([#41](https://github.com/seanome/kmerseek/pull/41))
- Added `hp_lehninger_hpc`, a 3-letter hydrophobic/polar/cystine alphabet that gives cysteine its own symbol, for detecting C2H2 zinc finger proteins ([#42](https://github.com/seanome/kmerseek/pull/42))
- Added nineteen reduced amino acid alphabets from Peterson 2009, Ieremie 2024, Rannon & Burstein 2026, and Jain 2014, collapsing the 20 residues into 2 to 20 classes, and renamed every alphabet so its name states its class count (`hp_lehninger` → `hp_lehninger2`, `hp_thomas_dill` → `hp_thomas_dill2`, and `hp_lehninger_hpc` from #42 → `hp_lehninger_hpc3`). The earlier kmerseek spellings are rejected rather than silently translated; the sourmash spellings `protein`, `dayhoff` and `hp` still resolve, to `protein20`, `dayhoff6` and `hp_lehninger2` ([#43](https://github.com/seanome/kmerseek/pull/43))
- Fixed `benches/benchmark.rs` calling `search_one` with the old two-argument signature, which broke `cargo clippy --all-targets` and `cargo bench` ([#44](https://github.com/seanome/kmerseek/pull/44))
- Replaced the invented protein sequences in the HP encoding tests with verbatim CED-9 (P41958) and BCL-2 (P10415) fragments from the test FASTA files ([#45](https://github.com/seanome/kmerseek/pull/45))
- Dropped any k-mer covering more than one ambiguous residue (B/J/Z), so disambiguating at most doubles the k-mers a sequence contributes instead of growing them as 2^*n*; #49 lifted this again ([#46](https://github.com/seanome/kmerseek/pull/46))
- Split the search cache across `search_cache_chunk_{i}` keys at 1 GiB each so an index whose serialized cache exceeds RocksDB's 4 GiB per-value limit can be written at all; a cache that fits keeps the single `search_cache` key byte for byte, so every existing index still loads ([#48](https://github.com/seanome/kmerseek/pull/48))
- Restored `--scaled` on `index` (removed in #30), with region detection that works on a sampled sketch: each surviving shared k-mer is grown back out along the stored sequences to the full exact match, so a reported region is always the whole match and `region_n_shared_kmers` counts only the k-mers the sample kept, with the region Poisson expectation summed over the same k-mers. `search` reads the value from the index and takes no flag. At k=10 indexing memory and index size fall almost linearly with the value (683 B to 87 B per residue from scaled 1 to 10); the cost is short matches none of whose k-mers survive the cutoff ([#50](https://github.com/seanome/kmerseek/pull/50))
- Indexed a k-mer covering *n* ambiguous residues (B/J/Z) under all 2^*n* readings, up to 10 per k-mer, instead of dropping it. At the default `--ksize 10` the earlier cap discarded every k-mer holding two, which left 1_982 UniRef50 clusters whose representative carries an ambiguous residue unsearchable at those positions. The worst real case, a pancreatic ribonuclease with 22 Bs and Zs in 124 residues (P00659), yields 541 readings at k=10 ([#49](https://github.com/seanome/kmerseek/pull/49))
- Streamed the index to disk during construction instead of holding every sketch, k-mer instance and the inverted index in memory, so indexing memory no longer grows with the corpus: 100_000 Swiss-Prot sequences went from 19.35 GB peak RSS to 2.21 GB and from 29 s to 10 s. New index schema (3): `targets_{n}` md5 chunks and 1024 `ii_shard_{s}` inverted-index shards replace the single `search_cache` value ([#51](https://github.com/seanome/kmerseek/pull/51))
- Added `region_tfidf` (sum of `ln(N / freq_target)` over the query k-mers inside the region) and `region_mean_idf` (that sum divided by the region's k-mer count) result columns, the region-scoped counterparts of `query_tfidf`, for ranking regions by how rare their k-mers are in the database ([#52](https://github.com/seanome/kmerseek/pull/52))
- Opened the index read-only when autodetecting search parameters, so several searches can start against one index at the same moment; before, they raced on the RocksDB `LOCK` file and 32 of 92 pipeline tasks died with `Resource temporarily unavailable` ([#53](https://github.com/seanome/kmerseek/pull/53))
- Extended each exact k-mer seed into an ungapped alignment until mismatches cost more than `--extend-xdrop` allows (`--extend-mismatch-penalty`, off by default), and ranked regions with a Karlin-Altschul E-value (`region_evalue`, `region_ka_bits`, `region_n_mismatches`), with K fitted on the index at build time (`--ka-queries`, `--ka-k`); `--chain-max-gap`/`--chain-max-shift` join colinear regions under sum statistics (`region_n_chained`). On 200 SCOPe40 domains the fraction of superfamily relatives found before the first different-fold hit rises from 0.0029 (exact k=23, Poisson) to 0.066 (extended k=12, E-value); MMseqs2 scores ~0.25 on the same queries ([#54](https://github.com/seanome/kmerseek/pull/54))
- Fixed `--remove-low-complexity` hashing a window covering B, J or Z with the literal ambiguous byte, so no query could match it; the three per-window loops now share one `Readings` iterator and `KmerEncoder` ([#56](https://github.com/seanome/kmerseek/pull/56), carried onto #57's rewrite of the same loops rather than merged)
- Disambiguated after alphabet encoding, so an ambiguous residue whose two readings land in the same class no longer doubles the k-mer's readings, and raised the per-k-mer ceiling from 10 to 20; matched regions now run through ambiguous residues instead of stopping at them. Tested with the 22-residue-ambiguous ribonuclease P00659 under all 19 alphabets ([#57](https://github.com/seanome/kmerseek/pull/57))
- Added `kmerseek pair`, which compares one query with one target and writes JSON with both encodings, every shared k-mer and its positions, and the matched regions; `scripts/visualize_pair.py` draws it as a dot plot with Pfam domains and one alignment block per run, and `scripts/visualize_search.py` turns a search CSV into a Foldseek-style HTML report per query ([#58](https://github.com/seanome/kmerseek/pull/58))
- Added the #52 `region_tfidf` and `region_mean_idf` columns to the `visualize_hits` test fixture, which checks the fixture carries every column `kmerseek search` writes ([#59](https://github.com/seanome/kmerseek/pull/59))
- Required the index schema version to equal the binary's; an older or newer index is refused with a message naming both versions and the kmerseek version that wrote it. Removed the schema 0/1/2 read paths (`search_cache`, `search_cache_chunk_{i}`, `signatures_chunk_{n}`) ([#60](https://github.com/seanome/kmerseek/pull/60))
- Fixed `cargo test` on `main` after #51 and #52 merged cleanly but disagreed on whether `ProteinSearcher::new` returns a `Result` ([#61](https://github.com/seanome/kmerseek/pull/61))
- Joined matched regions along each diagonal: shared positions are sorted by diagonal (target minus query position) before the run walk, so a k-mer that repeats in the target no longer splits one exact match into several regions. BCL-2 against itself at hp k=12 is one 239-residue region instead of a 45 and a 144; CED-9 against the 25-protein fixture reports 330 regions instead of 362. Whole-query statistics are unchanged ([#62](https://github.com/seanome/kmerseek/pull/62))
- Added `kmerseek calibrate`, which fits and stores the Karlin-Altschul lambda and K of an existing index for one more `--extend-mismatch-penalty`/`--extend-xdrop` pair, so a search at a second penalty reads a stored fit instead of refitting on every run ([#64](https://github.com/seanome/kmerseek/pull/64))
- `--ka-survival-out` (on `index` and `calibrate`) now writes the score histogram even when the fit is refused for too few score bins, with the fit columns empty and a `fitted` column saying so; the refusal message names the rule (4 bins above the peak with 30 regions each) instead of blaming the region count, and `scripts/plot_ka_survival.py` draws a refused curve without a line ([#64](https://github.com/seanome/kmerseek/pull/64))
- Fixed protein20 under extension: the sketch stores no encoded copy of a protein20 sequence (it equals the raw one), and the extension, the Karlin-Altschul fit and the E-value all read class compositions off the encoded copy, so every protein20 index fitted nothing (match probability 0) and every protein20 extended search came back exact with E = inf; all three now fall back to the raw sequence ([#64](https://github.com/seanome/kmerseek/pull/64))
- Reported every database entry that shares a sketch with a hit, under each of its names, and stopped dropping a hit on the query's own entry unless the search is all-vs-all: the index stores one signature per sketch md5, so a second entry with the same k-mer set used to vanish, and BCL-2 against a database holding `BCL2_HUMAN` never listed it. `aliases_{md5}` keeps the extra names; `SearchFilters::skip_self_matches` is on only in `search_all_vs_all` ([#63](https://github.com/seanome/kmerseek/pull/63))
